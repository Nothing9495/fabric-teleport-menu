# ui-lib 适配 Minecraft 26.3（ViaFabricPlus 高版本进低版本）可行性报告

结论：**当前无法产出可用的 26.3 版 ui-lib**。卡点不在本仓库代码本身，而在上游 UI 框架 owo-lib
没有 26.3 构建，且 26.x 的 owo 已是 0.13 线（本项目基于 0.12），属于跨大版本迁移，不是改一行版本号。

服务端（teleportmenu-2.3.0.jar）继续留在 1.21.1，无需改动；需要新增的是一个 **26.3 客户端构建**。

## 1. 已验证的版本事实（2026-11-22）

| 组件 | 现状 |
|---|---|
| Minecraft | `26.3` 为当前稳定版（Fabric meta） |
| Fabric Loader | `0.20.1`（26.3 对应） |
| Fabric API | `0.166.2+26.3`（最新 26.3 线） |
| owo-lib | 最新 `0.13.1+26.2`；Maven/Modrinth 均无 26.3 版本，GitHub 无 26.3 分支 |
| owo 26.2 的依赖声明 | `"minecraft": ">=26.1"`，不拒绝 26.3 加载，但未对 26.3 测试 |
| 构建工具链（26.3 模板） | Loom `1.19-SNAPSHOT`、Java **25**、**不混淆** MC（`implementation` 而非 `modImplementation`） |
| 本仓库现状 | Loom 1.15.5、Java 21、1.21.1 混淆 MC、owo `0.12.15.4+1.21` |

## 2. 为什么不能“只改版本号”

1. **owo 大版本不兼容**：本项目调用的是 owo 0.12 的 UI API；26.x 使用 owo 0.13，
   0.13 的 API 已经整体改名（实测 0.13.1+26.2 的 jar）：

   | 0.12（本项目） | 0.13（26.x） |
   |---|---|
   | `io.wispforest.owo.ui.core.Component` | `io.wispforest.owo.ui.core.UIComponent` |
   | `ParentComponent` | `ParentUIComponent` |
   | `ComponentStub` / `GreedyInputComponent` | `UIComponentStub` / `GreedyInputUIComponent` |
   | `GuiGraphics` + `render(...)` | `GuiGraphicsExtractor` + `extractRenderState/extractBackground` |
   | `keyPressed(int,int,int)` / `mouseDragged(double,double,int,double,double)` | `keyPressed(KeyEvent)` / `mouseDragged(MouseButtonEvent,double,double)` |
   | `io.wispforest.owo.ui.component.Components` | 该类在 0.13.1 中已不存在（改名/迁移） |

   MC 26.x 本身也换了 GUI 事件与渲染模型，11 个自绘控件（`AbstractOreButtonWidget` 等）
   的 `renderWidget(GuiGraphics, ...)` 重写全部失效，需要按新模型重写。
2. **MC 26.3 是 unobfuscated 版本**：Loom 配置、依赖写法（`implementation`）、映射方式都与 1.21.1 项目不同，
   现有 `build.gradle` 不能直接复用。
3. **Java 25**：26.3 的 `options.release = 25`，本机当前只有 JBR 21，需要额外安装 JDK 25 才能编译。
4. **owo 没有 26.3 构建**：即使源码迁移完成，运行时也只能拿 26.2 的 owo 冒险加载；
   Mixin 目标在 26.3 是否仍存在未经上游验证。

## 3. 两种可行路线

### 路线 A（推荐）：等 owo 26.3，再做机械迁移

owo 作者对每个版本跟进很快（26.1、26.2 均有发布）。上游发布 26.3 后：

1. 新建独立构建目录（不入根构建，避免破坏 1.21.1 版本）：
   - `version-26.3/settings.gradle`、`gradle.properties`（MC 26.3 / Loader 0.20.1 / Fabric API 0.166.x+26.3 / owo 0.13.x+26.3 / Loom 1.19）
   - `version-26.3/build.gradle`，`srcDir "../src/client/java"` 复用同一套界面源码
   - `version-26.3/src/main/resources/fabric.mod.json`（`"minecraft": ">=26.3 <26.4"`，与 1.21.1 包分开分发）
2. 安装 JDK 25，`options.release = 25`。
3. 编译并修复 MC 26.x API 差异（预计集中在 `GuiGraphics`/渲染、`MultiLineEditBox`、`CustomPacketPayload`、`DisplaySlot`）。
4. 迁移 owo 0.12 → 0.13 调用（`Components`/`Containers`/`Sizing`/`Surface`/`BaseOwoScreen`）。
5. 端到端验收（见第 4 节）。

预计工作量：上游就绪后 3–5 个工作日（约 40 个客户端类 + 11 个自绘控件的 API 迁移、事件/渲染模型重写、实机回归），
且需要 JDK 25 与 Loom 1.19。

### 路线 B（不依赖 owo）：26.3 专用原生控件版

用原版 `Screen` + `Button` + `AbstractSelectionList` + `EditBox` 重写界面，彻底摆脱 owo。
优点：不受 owo 发布节奏影响；缺点：约 30 个界面需要重写（2000–4000 行），且要和 1.21.1 版长期双维护。
适合“必须马上支持 26.3”的场景。

## 4. 验收清单（任一版本构建都必须通过）

- [ ] 1.21.1 客户端 + 1.21.1 服务端：现有功能不回归
- [ ] 26.3 客户端 + ViaFabricPlus + 1.21.1 服务端：时钟打开菜单
- [ ] 自定义负载通道（`teleportmenu:*`）经 Via 翻译后仍能收发（重点风险：Via 对 mod 自定义包的透传）
- [ ] 动态、商店、领地、家点、点赞/删除、草稿等全部走一遍
- [ ] 计分板隐藏、奖励提示过滤、`/help` 客户端指令在 26.3 下正常（客户端 API 变动会影响 `ClientReceiveMessageEvents`）

## 5. 当前状态

- `build/libs/teleportmenu-2.3.0.jar`、`ui-lib/build/libs/teleportmenu-ui-2.3.0.jar`：**仅 1.21.1**，不可用于 26.3 客户端。
- 未创建 26.3 构建目录：在 owo 26.3 缺失、JDK 25 未安装前，该目录无法编译，放入构建只会制造失败产物。
